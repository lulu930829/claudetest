# /project:deploy

执行项目部署流程，支持不同环境部署。

## 参数

- `--env=<环境>` 部署环境：dev、staging、production
- `--dry-run` 干运行（不实际部署）
- `--force` 强制部署（跳过某些检查）
- `--version=<版本>` 指定部署版本

## 部署环境

### 开发环境 (dev)

- 目标：快速验证功能
- 流程：自动构建和部署
- 验证：基本功能测试

### 预发布环境 (staging)

- 目标：集成测试
- 流程：完整构建 + 人工验证
- 验证：完整测试套件

### 生产环境 (production)

- 目标：正式发布
- 流程：严格审查 + 分阶段部署
- 验证：全面测试 + 监控

## 工作流程

### 1. 前置检查

- 代码状态检查（无未提交更改）
- 分支检查（正确分支）
- 依赖检查（包版本）

### 2. 质量检查

- 运行完整测试套件
- 代码质量检查（ESLint）
- 类型检查（TypeScript）
- 安全扫描

### 3. 构建阶段

- 清理构建目录
- 生产环境构建
- 资源优化
- 生成构建报告

### 4. 验证阶段

- 构建产物验证
- 基本功能测试
- 性能基准测试
- 兼容性检查

### 5. 部署阶段

- 备份当前版本
- 部署新版本
- 更新版本信息
- 清理临时文件

### 6. 后置检查

- 部署状态验证
- 健康检查
- 监控配置
- 通知相关方

## 安全措施

- 生产部署需要明确确认
- 自动回滚机制
- 部署日志记录
- 访问权限控制

## 输出

- 部署报告
- 构建日志
- 测试结果
- 部署状态

## 示例

```bash
# 开发环境部署
/project:deploy --env=dev

# 预发布环境干运行
/project:deploy --env=staging --dry-run

# 生产环境部署（需要确认）
/project:deploy --env=production --version=1.2.3
```
