# /project:fix-issue

修复项目中的问题、Bug或技术债务。

## 参数

- `--type=<类型>` 问题类型：bug、security、performance、refactor、test
- `--file=<文件>` 修复指定文件
- `--issue=<编号>` 关联的问题/PR编号
- `--priority=<优先级>` high、medium、low

## 工作流程

1. **问题分析**
   - 复现问题（如可能）
   - 分析根本原因
   - 确定影响范围

2. **解决方案设计**
   - 设计修复方案
   - 考虑向后兼容性
   - 评估测试影响

3. **代码修复**
   - 实现修复代码
   - 更新相关文档
   - 调整配置（如需要）

4. **测试验证**
   - 编写/更新测试用例
   - 运行现有测试套件
   - 验证修复效果

5. **代码质量**
   - 运行代码检查
   - 确保代码规范
   - 更新类型定义

## 支持的问题类型

### Bug修复

- 逻辑错误
- 边界条件处理
- 异步问题
- 状态管理问题

### 安全修复

- XSS漏洞
- 数据验证问题
- 敏感信息泄露
- 依赖安全更新

### 性能优化

- 渲染性能
- 内存泄漏
- 网络请求优化
- 包体积优化

### 重构

- 代码重复
- 复杂度过高
- 设计模式改进
- 架构调整

### 测试改进

- 缺失测试
- 脆弱测试
- 测试性能
- 覆盖率提升

## 输出

- 修复报告
- 更改文件列表
- 测试结果
- 建议的后续操作

## 示例

```bash
# 修复ESLint报告的问题
/project:fix-issue --type=refactor

# 修复特定文件的安全问题
/project:fix-issue --type=security --file=src/api/request.ts

# 高优先级Bug修复
/project:fix-issue --type=bug --priority=high
```
